# ADR 0003. 라우터 스킬과 wizard 스킬을 들이지 않는다

- 상태: 채택
- 날짜: 2026-08-13
- 관련: #253, #254(닫힘), #256(닫힘), `mattpocock/skills` v1.2.3 (MIT)

## 배경

`mattpocock/skills` 를 대조 원본으로 놓고 이 레포에 없는 것을 골라냈다. 여섯 개가 후보로 올라왔고 넷은 채택했다. 나머지 둘을 이 문서가 다룬다.

기각을 이슈로 열어 두면 남은 이슈가 되고, 남은 이슈는 시간이 지나 부채로 읽힌다. 기각도 판단이므로 판단을 기록에 남기고 이슈는 닫는다. 이 문서의 목적은 같은 후보가 다시 올라왔을 때 근거 없이 채택되는 것을 막는 데 있다.

## 결정

### 1. 스킬 라우터를 만들지 않는다

원본의 `ask-matt` 은 스킬 목록과 스킬 간 관계를 한 문서에 담아, 상황을 말하면 어느 스킬이 맞는지 안내한다.

트리거가 겹치는 구간은 실재한다. 측정한 네 곳이다.

| 겹침 | 반응하는 스킬 |
|------|---------------|
| `content-write` | 이 레포와 외부 플러그인에 같은 이름이 있다 |
| "검증" | `content-verify` 와 `cross-verify` |
| "발행" | `content-publish` 와 외부 발행 스킬 |
| "이슈" | `flow` 와 `org-flow` |

그런데도 만들지 않는 이유는 라우터의 유지 비용이 겹침의 비용보다 크기 때문이다. 라우터는 스킬을 추가·개명·삭제할 때마다 함께 고쳐야 하고, 낡은 라우터는 없는 라우터보다 나쁘다. 없으면 사용자가 직접 고르지만 낡으면 틀린 곳으로 보낸다. 현재 운영자는 한 명이고 자기 스킬 목록을 안다. 라우터가 대신 알아 줄 것이 없다.

### 2. wizard 스킬을 만들지 않는다

원본의 `wizard` 는 사람만 할 수 있는 단계를 대화형 bash 스크립트로 생성한다. `docs/external-auth.md` 가 규정하는 "브라우저 동의 명령은 사용자에게 제시하고 어시스턴트가 대신 실행하지 않는다" 구간과 대상이 같다.

만들지 않는 이유는 빈도다. 왕복이 실제로 반복되는 구간은 신규 provider 등록 하나뿐이고, 조직 어댑터 쪽에 키체인 스크립트가 이미 있다. 스킬 하나를 상주시켜 얻는 것이 그 하나의 왕복을 줄이는 것이면 컨텍스트 부하가 값을 못 한다 (`config/style-rules/base/authoring.md` AU2).

## 다시 열어야 하는 조건

기각은 지금 조건에서의 판단이다. 아래가 관찰되면 이 ADR 을 갱신하고 다시 판단한다.

| 후보 | 다시 여는 조건 |
|------|----------------|
| 라우터 | 이 레포의 스킬을 운영자 외의 사람이 쓰기 시작할 때. 남이 쓰면 "어느 스킬이 맞나" 가 매일 나오는 질문이 되고, 그때는 라우터 유지 비용보다 겹침 비용이 커진다 |
| 라우터 | 스킬 수가 늘어 겹치는 트리거가 네 곳을 넘어갈 때 |
| wizard | 신규 provider 등록 외에 사람 전용 다단계 설정이 하나 더 생길 때. 두 곳이 되면 절차를 옮겨 적는 자리가 두 곳이 되므로 생성기가 값을 한다 |

## 기각한 대안

**라우터를 만들되 갱신을 hook 으로 강제한다.** 스킬 디렉토리가 바뀌면 라우터 갱신을 요구하는 검사를 붙이는 방안이다. 낡음은 막지만 라우터가 존재해야 할 이유를 만들어 주지는 않는다. 유지할 값이 없는 문서에 유지 장치를 다는 것은 비용을 두 번 내는 일이다.

**겹치는 트리거를 좁혀 겹침 자체를 없앤다.** 트리거를 좁히면 자연어 라우팅의 도달률이 떨어진다. 사용자가 규칙에 맞는 말을 골라야 하는 상태가 되므로 자연어 라우팅을 쓰는 이유가 사라진다. 겹침은 남기고 사용자가 고르는 현재 방식을 유지한다.
