# 컨벤션 선언 슬롯

커밋·체인지로그 **표기**를 org·repo 단위로 선언하는 자리. 표기를 강제하지 않고, 선언이 없을 때만 ops-agent 기본값이 적용된다.

사슬(변경 종류 → 체인지로그 분류 → 버전 증분)은 환경과 무관하므로 `skills/flow/guides/commit.md` 가 보유한다. 이 문서가 다루는 것은 그 사슬을 어떤 문자열로 표기하는지다.

## 왜 슬롯이 필요한가

`commit.md` 는 ops-agent 를 설치한 모든 레포에 적용되는 산출물이다. 이미 컨벤션이 정착된 레포에 다른 표기를 들이미면 두 가지가 끊긴다.

- **이력 조회**: 타입 어휘가 바뀌면 `git log --grep` 기반 조회가 경계에서 끊긴다
- **자동화 결합**: 커밋 제목이나 체인지로그 형식을 파싱하는 도구가 있으면 그 형식은 문서가 아니라 계약이다. 바꾸면 파이프라인이 빈 결과를 낸다

트래커가 제목에 티켓 번호를 요구하는 레포처럼, 표기를 바꿀 수 없는 환경이 실재한다.

## 위치

| 계층 | 경로 | 비고 |
|---|---|---|
| repo | `~/.claude/ops-agent/repos/<owner>--<repo>.json` | 레포 단위 선언 |
| org | `~/.claude/ops-agent/orgs/<owner>.json` → `conventions` 키 | 멀티레포 스킬이 쓰는 기존 매니페스트를 재사용한다. 신규 파일을 만들지 않는다 |
| org (외부 어댑터) | `<adapterRoot>/<adapter>/orgs/<owner>.json` | 외부 어댑터 org 의 기존 매니페스트는 여기 있다. 어댑터 루트는 `~/.claude/ops-agent/adapters.json` 이 선언한다 |

세 번째 줄이 없던 동안, 규약대로 기존 매니페스트에 `conventions` 를 선언하면 해석되지 않았다. 해석되게 하려고 `orgs/<owner>.json` 을 새로 만들면 같은 이름 파일이 두 위치에 생겨 어느 쪽을 쓸지 규정되지 않는다. 위 순서가 그 판정이다.

`<owner>` · `<repo>` 는 **git remote 에서 얻는다**. 디렉토리 이름으로 추론하지 않는다. CI 러너의 임의 클론 경로, 다른 사람의 클론 위치, 상위 디렉토리를 거치지 않은 직접 진입에서 모두 깨진다. remote 는 클론 위치·세션 습관과 무관하게 불변이다.

식별과 발견은 [`scripts/resolve-manifest.mjs`](../scripts/resolve-manifest.mjs) 한 곳에서 한다. org-flow 와 commit 단계가 같은 해석기를 쓴다. 규칙을 두 벌로 두면 한쪽에 선언한 값이 다른 쪽에서 읽히지 않는다.

```bash
node ~/.claude/ops-agent/current/scripts/resolve-manifest.mjs
```

해석 실패와 대체 경로 사용은 `notes` 에 담겨 나온다. 조용히 기본값으로 떨어지지 않는다.

## 해석 순서

```text
레포 선언  >  org 기본값  >  ops-agent 기본값
```

레포 선언이 항상 이긴다. org 기본값을 우선하면 자기 컨벤션을 가진 레포가 중앙값에 덮인다. 조직이 커질수록 "기존 레포는 자기 선언대로, 신규 레포만 중앙 기본값" 이 현실이므로, 상속을 우선으로 두면 규모가 커질 때 규칙을 다시 뒤집어야 한다.

한 레포에 선언이 일부만 있으면 나머지 키만 상위에서 채운다 (키 단위 병합).

## 스키마

```json
{
  "conventions": {
    "inheritMode": "live",
    "commitTypes": ["feat", "fix", "docs", "refactor", "chore", "ci"],
    "subjectFormat": "{type}: {subject}",
    "changelogSections": {
      "Added": "Added",
      "Changed": "Changed",
      "Deprecated": "Deprecated",
      "Removed": "Removed",
      "Fixed": "Fixed",
      "Security": "Security"
    }
  }
}
```

| 키 | 타입 | 설명 |
|---|---|---|
| `inheritMode` | `"live"` \| `"seed"` | 아래 "상속과 시딩" 참조. 기본 `live` |
| `commitTypes` | string[] | 이 레포·org 가 쓰는 커밋 타입 어휘. 레포에 존재하지 않는 단계는 넣지 않는다 |
| `subjectFormat` | string | 제목 형식. `{type}` · `{scope}` · `{ticket}` · `{subject}` 치환. 트래커가 번호 접두를 요구하면 여기서 표현한다 |
| `changelogSections` | object | 6종 분류의 표시 이름. 한국어 섹션명을 쓰는 레포는 값만 바꾼다. 키는 바꾸지 않는다: 사슬이 키를 기준으로 동작한다 |

모든 키는 선택이다. 없는 키는 상위 계층에서 채워진다.

## 상속과 시딩

갈림 기준은 레포 수도 조직 규모도 아니라 **변경 권한의 소유권**이다. 판정 질문 하나로 갈린다.

> 이후에도 중앙이 그 레포의 동작을 바꿀 자격이 있는가?

| 모드 | 동작 | 맞는 상황 |
|---|---|---|
| `live` | 레포가 org 매니페스트를 계속 참조한다. 중앙을 고치면 참조하는 레포가 즉시 따라온다 | 중앙과 레포를 같은 사람들이 실제로 함께 운영한다 |
| `seed` | 셋업 시점에 org 값을 레포 선언으로 **복사**한다. 이후 중앙 변경과 무관하게 레포가 독자 진화한다 | 구축 후 담당자에게 넘긴다. 소유권이 이전됐다 |

이관된 레포를 `live` 로 두면 중앙 수정이 다른 담당자의 레포 동작을 소리 없이 바꾼다. 넘긴 레포에 원격 조종 줄이 남는 셈이다.

`seed` 는 셋업 1회 동작이므로, 복사 후에는 레포 선언만 읽는다. org 값을 다시 끌어오려면 명시적으로 재시딩한다.

## 레포 표면에 남기지 않는다

슬롯은 레포 **밖**(`~/.claude/ops-agent/`)에 둔다. 레포 안에 두면 무시 규칙이 필요해지고, `.gitignore` 항목 자체가 그 도구를 쓴다는 노출이다. 퍼블릭 레포에서는 그 한 줄이 정보가 된다.

심링크는 해결책이 아니다. git 은 심링크를 일반 blob 으로 다루므로 추적되지 않은 파일로 그대로 표시된다. 무시 규칙이 다시 필요해져 원점으로 돌아온다.

레포 안에 있어야만 하는 도구가 있으면 `.git/info/exclude` 를 쓴다. 추적되지 않으므로 레포 표면에 남지 않고, 연결된 워크트리도 공유 `.git` 의 값을 상속한다. 다만 클론 시 사라지므로 설치 스크립트가 다시 심어야 한다.

## 읽는 주체

슬롯은 **commit 단계 진입 시 가이드가 읽는다**. 세션 시작에 주입하지 않는다: 매 세션 토큰을 쓰면서 대부분의 세션에서 쓰이지 않는다.

읽고 아무도 소비하지 않는 설정을 만들지 않는다. `overlays/` 가 그 상태다: 세션 시작에서 로딩되고 "loaded" 만 출력되며 어떤 키도 해석되지 않는다. 슬롯은 소비 주체를 먼저 정하고 도입한다.

## 선언이 없을 때

`commit.md` 의 판정 순서를 따른다.

1. 선언 슬롯이 있으면 그것이 정본
2. 없으면 최근 이력 표본으로 표기를 추정하고 **사용자에게 확인**
3. 둘 다 없으면 `commit.md` 의 기본값

2단계에서 이력을 읽되, 읽은 결과를 정본으로 삼지 않는다. 이력은 여러 시대가 섞여 있을 수 있어 그대로 따르면 과거의 중단된 관행을 되살린다.
