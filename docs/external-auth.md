# 외부 서비스 인증

에이전트가 외부 서비스 CLI 를 호출하다 인증 만료를 만났을 때 무엇을 할지 정한다.

## 원칙

**토큰 발급을 권하지 않는다. 그 서비스의 정식 인증 명령을 사용자에게 제시한다.**

만료를 만나면 가장 손쉬운 회피책이 "장수 API 토큰을 발급해 보관" 이다. 그 회피책은 비용을 옮기기만 한다.

- 비밀값이 기기에 종속된다. 기기를 옮기면 재발급하거나 어딘가 적어야 한다
- 보관 위치를 사람이 기억해야 한다
- 스코프가 과해지기 쉽다. 필요한 권한만 고르는 판단을 매번 다시 한다

대상 서비스가 브라우저 동의 기반 인증을 이미 제공하는 경우가 많다. 그 경로를 쓰면 사람이 손으로 다룰 비밀값이 없다.

### 이득을 정확히 말한다

정식 인증도 갱신 토큰을 디스크에 둔다. 이득은 "보관이 사라진다" 가 아니라 **"사람이 손으로 다룰 비밀값이 사라진다"** 다. 기기 이동·기억·스코프 판단이 없어지는 것이 실제 이득이다.

보관 위치는 서비스 구현에 달렸고, 평문 파일에 두는 CLI 도 있다. 그 사실을 숨기지 않고 알린다.

## 만료를 만났을 때

1. 인증 만료임을 확인한다 (권한 부족과 구분한다)
2. 아래 표에서 그 서비스의 정식 인증 명령을 찾는다
3. 사용자에게 명령을 제시한다. **어시스턴트가 대신 실행하지 않는다** — 브라우저 동의는 사람만 할 수 있다
4. 인증 후 원래 작업을 재개한다

브라우저 콜백이 필요한 명령은 세션 내 `!` 실행이 아니라 **사용자 본인 터미널**을 권한다. TTY 가 아니면 콜백이 걸린다.

### 스코프 밖 작업은 처음부터 사용자 몫으로 안내한다

정식 인증의 스코프는 그 CLI 가 요청한 범위로 고정돼 있다. 그 범위를 넘는 작업은 인증을 다시 해도 되지 않는다.

권한을 넓히려고 별도 비밀값을 만들지 않는다. 스코프 밖 작업은 처음부터 사용자가 콘솔에서 하는 것으로 안내한다. 한 번 하고 끝나는 작업이면 그게 더 빠르다.

## 서비스별

| 서비스 | 정식 인증 | 지원 그랜트 | 스코프 밖 (실측) |
|--------|-----------|-------------|------------------|
| GitHub (`gh`) | `gh auth login` | Device Authorization, Authorization Code | — |
| Cloudflare (`wrangler`) | `wrangler login` | **Authorization Code + PKCE 만** | DNS 쓰기. 27개 스코프에 `dns` 없음 → 콘솔에서 처리 |

### 그랜트 타입은 클라이언트가 고르지 않는다

어떤 흐름을 쓸 수 있는지는 **인증 서버가 무엇을 구현했는지**로 결정된다. CLI 쪽에서 선택하는 항목이 아니다.

| 흐름 | 사람이 하는 일 | 전제 |
|------|----------------|------|
| Authorization Code + PKCE (loopback) | 같은 기기 브라우저에서 승인 | 브라우저가 같은 기기에 있어야 한다 |
| Device Authorization | 다른 기기에서 주소 열고 승인. CLI 는 폴링 | 브라우저 없는 기기에서도 된다 |

Device Authorization 의 존재 이유는 보관을 없애는 것이 아니라 **브라우저와 토큰 받는 쪽이 같은 기기가 아니어도 되게 하는 것**이다. SSH·CI·헤드리스가 대상이다.

지원하지 않는 서비스가 있다. Cloudflare 는 문서에서 Device Authorization 을 명시적으로 배제한다. 표에 실제 지원 방식을 적어 두고, 기억으로 판단하지 않는다.

### 자기 서비스에 OAuth 를 붙이는 경우는 반대편이다

자기 API 에 인증을 구현하는 쪽이라면 그랜트 선택권이 있다. 헤드리스 소비자를 지원해야 하면 Device Authorization 을 구현할 수 있다.

이 문서는 **남의 인증 서버를 쓰는 소비자** 입장을 다룬다. 두 상황을 같은 문제로 보면 안 된다.

## 토큰 보관이 불가피한 경우

다음을 **모두** 만족할 때만 예외로 둔다.

- 그 서비스가 브라우저 동의 기반 인증을 제공하지 않는다
- 또는 사람이 없는 환경에서 무인 실행해야 한다 (CI·스케줄러)
- 필요한 권한만으로 스코프를 좁힐 수 있다
- 만료·폐기 경로가 있다 (TTL 또는 콘솔 삭제)

이 경우 보관은 OS 보안 저장소를 쓰고 평문 파일·레포·로그에 남기지 않는다. 값은 사용자가 본인 터미널에서 입력하게 하고, 대화에 붙여넣지 않게 안내한다.

```bash
read -rs TOKEN && <저장 명령> && unset TOKEN
```

OS 보안 저장소는 평문 파일을 없애는 장치이고, **같은 로그인 세션에서 실행되는 코드로부터는 보호하지 않는다.** 그래서 대응은 접근 통제가 아니라 권한 최소화와 주기적 폐기다.
