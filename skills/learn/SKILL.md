# 레슨런 승격

작업 세션을 기존 레슨런 자산과 대조해 승격 여부를 판정한다. 용어·절차·재발 분석은 [docs/lessons.md](../../docs/lessons.md) 가 정본이며 여기서 재정의하지 않는다.

## 판정 입력

두 가지를 함께 본다. 어느 하나로 대체하지 않는다.

| 입력 | 성격 |
|------|------|
| Stop 훅 후보 (`~/.claude/lesson-candidates.jsonl`) | 예비 신호. 정규식이 잡은 것만 들어 있다 |
| 작업 세션 트랜스크립트 | 판정 근거. 훅이 놓친 교정과 자산 재발이 여기에만 있다 |

**후보가 0건이어도 세션 대조는 한다.** 후보 파일만 읽으면 정규식이 놓친 교정은 재발 대조가 시작되지 않는다. 그 재발은 없었던 것이 된다. 검출 패턴은 부정어 중심이라 지시형·질문형 교정을 놓친다. 오판을 짚는 발화일수록 그 형태로 나온다.

### 후보 파일 필드

한 줄이 후보 1건이다. 사용자 발화 원문이 들어가므로 로컬 전용이고 레포에 커밋하지 않는다.

| 필드 | 내용 |
|------|------|
| `capturedAt` | 적립 시각 |
| `session` · `transcript` | 원본 포인터. 등재 시 그대로 옮긴다 |
| `cwd` | 발생 위치 |
| `signals` | 검출된 신호 라벨 |
| `excerpt` | 사용자 발화 앞 400자 |

## 절차

1. 후보 파일과 세션 트랜스크립트를 모은다
2. 세션에서 교정을 추린다. 후보에 없어도 교정이면 센다. 후보에 있어도 단순 방향 전환·취향 변경이면 뺀다. **추린 수를 적어 둔다.** 검출률의 분모가 이 수다
3. 소비 프로젝트의 레슨런 버킷 전체와 대조해 갈래를 정한다
4. 게이트 3종을 통과시킨다
5. 통과분만 등재한다. 등재와 로컬 인덱스 요약은 한 동작이다
6. 판정 요약을 남긴다 ([판정 요약 기록](#판정-요약-기록-필수))
7. 처리한 후보를 원본에서 옮긴다

### 갈래

| 판정 | 조치 |
|------|------|
| 신규 | 게이트를 걸고 등재안을 올린다 |
| 재발 | 새 파일을 만들지 않는다. 발생 이력을 더하고 분석으로 보낸다 |
| 무효화 | 자산이 지금 사실과 어긋난다. 사상 수정 또는 삭제 후보로 올린다 |
| 없음 | 아무것도 만들지 않는다 |

3번 대조는 자산 전체를 읽어야 하고 세션도 길다. 컨텍스트 비용이 크므로 서브에이전트에 위임하고 결론만 받는다. 위임할 때는 요약이 아니라 원본 경로를 넘긴다. 요약본을 받은 판정자가 원본을 받은 쪽보다 나빴다는 결과가 있다.

## 게이트

| 게이트 | 판정 |
|--------|------|
| 사실 확인 | 원천이 실제로 그 파일·그 위치에 있는가. 원천이 최신 사실과 맞는가 |
| 모순 확인 | 기존 레슨런과 충돌하지 않는가 |
| 일반화 확인 | 한 번의 변동을 규칙으로 굳히는 건 아닌가 |

통과하지 못한 후보는 기각으로 기록한다. 기각률이 이 절차의 자기 점검 지표다.

## 무효화

게이트의 사실 확인은 등재 시점에만 걸린다. 등재된 뒤로는 자산이 다시 검사받지 않으므로, 대조하면서 만난 자산이 **지금도 사실인가**를 함께 본다.

낡은 자산은 없는 것보다 나쁘다. 자산이 있으면 확인을 대신하는데, 그 값이 틀렸으면 확인을 건너뛴 채로 틀린다.

| 신호 | 조치 |
|------|------|
| 자산이 가리키는 파일·플래그·경로가 사라졌다 | 삭제 후보 |
| 근거는 남았으나 결론이 달라졌다 | 사상 수정 후보 |
| 조건이 좁아졌다 (특정 버전·환경에서만 성립) | 적용 범위를 자산에 적는다 |

삭제·수정은 등재와 같이 사람 승인을 거친다. 판정자가 바로 지우지 않는다.

## 등재 시 필수

- **원본 포인터를 남긴다.** `session`·`transcript` 를 레슨런 파일에 옮긴다. 요약만 남기면 잃은 신호를 되짚을 수 없다
- **로컬 인덱스 요약을 함께 쓴다.** 원격 등재만으로는 다음 판단 시점에 닿지 않는다. 실제로 등재 직후 같은 오판이 재발한 사례가 있다
- **재발 횟수를 요약에 적지 않는다.** 본문 서술·버킷 인덱스·로컬 인덱스에는 `최다 재발` 같은 서열 표현만 쓴다. 숫자를 적으면 다음 등재에서 그 자리가 낡고, 낮게 굳은 값이 재발 분석의 입력이 된다 ([docs/lessons.md](../../docs/lessons.md) 파일 규약)
- **발생 이력에 작업 식별자를 적는다.** 날짜만 적으면 재발 간격을 작업 수로 셀 수 없다. 트래커가 없으면 세션 식별자(`session:<앞 8자리>`)를 쓴다. 작업끼리 구분되는 값이어야 한다 ([docs/lessons.md](../../docs/lessons.md) 파일 규약)

## 판정 요약 기록 (필수)

승격이 끝나면 세션 단위로 아래를 남긴다. **지금 적지 않으면 복구되지 않는다.** 세션 대조 결과는 판정과 함께 사라지고, 후보 파일에는 훅이 잡은 것만 남아 분모가 없다.

| 값 | 뜻 |
|-----|-----|
| 교정 수 | 세션 대조로 교정이라 판정한 수. 검출률의 분모. 한 발화에 교정이 둘이면 2로 센다 |
| 유효 후보 수 | 훅 적립분 중 실제 교정인 수. 검출률의 분자. 오탐은 빼고 센다 |
| 오탐 수 | 적립됐으나 교정이 아니었던 수. 훅 신호를 볼 때 쓴다 |
| 승격·재발·기각 | 갈래별 건수. 기각률의 입력 |
| 판정일 | 이 판정을 끝낸 날 |

기록 위치는 소비 프로젝트가 정한다. 지표 정의는 [docs/lessons.md](../../docs/lessons.md) 가 갖고 값은 소비 프로젝트가 갖는다.

## 후보 정리 (필수)

처리분은 지우지 않고 옮긴다. 기각 이력도 지표에 쓰인다.

**이 단계를 건너뛰면 다음 승격이 같은 후보를 다시 훑는다.** 분모가 쌓이지 않아 기각률도 나오지 않는다. 승격이든 기각이든 판정을 끝냈으면 옮긴다.

```bash
python3 - <<'PY'
import json, os
src = os.path.expanduser("~/.claude/lesson-candidates.jsonl")
dst = os.path.expanduser("~/.claude/lesson-candidates.processed.jsonl")
keep, moved = [], []
handled = {"<처리한 excerpt 앞부분>"}   # 승격·기각 판정을 끝낸 후보
for line in open(src):
    rec = json.loads(line)
    (moved if any(h in rec["excerpt"] for h in handled) else keep).append(line)
with open(dst, "a") as f:
    f.writelines(moved)
with open(src, "w") as f:
    f.writelines(keep)
print(f"moved={len(moved)} keep={len(keep)}")
PY
```

## 하지 않는 것

- 자동 등재. 훅은 후보 적립까지만 하고 승격은 사람 확인을 거친다
- 자동 삭제. 무효화 판정도 사람 승인을 거친다
- 재발을 차단 규칙 추가로 처리. 재발은 분석으로 보낸다
- 후보 파일만 읽고 끝내기. 후보 0건도 세션 대조 대상이다
- 후보 파일 커밋

## 경계

버킷 경로와 프론트매터 필드 이름은 소비 프로젝트가 정한다. 정의가 없으면 어디에 둘지 확인하고 멈춘다. 추측해서 새 위치를 만들지 않는다.
