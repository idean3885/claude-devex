# 문서 유형 프로필

각 익스텐션이 반복하던 세 절(`적용 대상` · `base 대비 적용 강도` · `합격선`)을 한곳에 모은 표다. 이 세 절은 규칙이 아니라 유형마다 값만 달라지는 자리이므로, 유형이 늘면 파일이 아니라 행이 하나 는다.

익스텐션 파일에는 그 유형의 고유 규칙과 `필수 구조` 만 남는다. 유형별 파라미터는 여기가 정본이다.

| 유형 | 익스텐션 | 접두 |
|------|----------|------|
| 블로그 | [blog.md](blog.md) | `B` |
| 위키 | [wiki.md](wiki.md) | `W` |
| 정보성 | [info.md](info.md) | `I` |
| 지식 | [knowledge.md](knowledge.md) | `K` |
| PoC | [poc.md](poc.md) | `PC` |
| 이슈 | [issue.md](issue.md) | `ISS` |
| 장표 | [deck.md](deck.md) | `D` |
| 아키텍처 | [architecture.md](architecture.md) | `AR` |
| 데일리로그 | [dailylog.md](dailylog.md) | `DL` |
| 동료리뷰 | [peer-review.md](peer-review.md) | `PR` |
| 성과평가 | [work-review.md](work-review.md) | `WR` |

---

## 1. 적용 대상

어떤 매체에 어떤 익스텐션이 걸리는지를 정한다. 두 익스텐션이 함께 걸리는 조합은 `적용` 열에 명시한다.

| 유형 | 매체 | 적용 |
|------|------|------|
| 블로그 | Jekyll Chirpy 블로그 (`{your-blog}.github.io`) | `blog` |
| 블로그 | 외부 기술 블로그 (Medium·Velog·tistory 등) | `blog` + 매체별 메타 가공 |
| 위키 | 위키 provider 본문 | `wiki` |
| 위키 | 블로그 발행 전 원본 | `wiki` → 발행 시 마스킹 거쳐 `blog` 로 전환 |
| 정보성 | 설정 가이드·트러블슈팅 | `info` |
| 정보성 | API 사용 가이드 | `info` |
| 정보성 | 절차 안내 (배포·릴리스·온보딩) | `info` |
| 지식 | 위키 개발 사전 (재참조용) | `knowledge` |
| 지식 | 블로그 "기술 노하우 / 개발 사전" 카테고리 | `knowledge` + `blog B6` 메타 |
| PoC | PoC 문서 (위키·레포 `.docs/`) | `poc` |
| PoC | 블로그 PoC 회고 | `blog` + `poc` 의 결론 선행·재현 가능성 항목 |
| 이슈 | 이슈 트래커 태스크 본문 | `issue` |
| 이슈 | GitHub·GitLab·Jira 이슈 | `issue` |
| 장표 | 비교·판단을 전달하는 페이지·슬라이드 | `deck` |
| 장표 | 블로그에 실리는 비교 장표 | `blog` + `deck` |
| 아키텍처 | 레포 설계 문서 (`docs/ARCHITECTURE.md` 등) | `architecture` |
| 아키텍처 | 위키·블로그의 설계 소개 | `architecture` + 매체 익스텐션 |
| 아키텍처 | PoC 의 구조 설명 절 | `poc` + `architecture` 의 시점·정지 조건 |
| 데일리로그 | 데일리로그 (이슈 트래커 프로젝트) | `dailylog` |
| 데일리로그 | 주간 리포트 (월요일 통합) | `dailylog` + 분량 완화 |
| 동료리뷰 | 조직장 참고용 동료 평가 | `peer-review` |
| 동료리뷰 | 360도 리뷰 | `peer-review` + 익명 처리 |
| 성과평가 | 연말 성과평가 자기 기술서 | `work-review` |
| 성과평가 | 분기 성과 회고 | `work-review` + 분량 완화 |

## 2. base 대비 적용 강도

base 규칙의 강도를 유형마다 올리거나 내린다. 여기 없는 규칙은 base 값을 그대로 쓴다.

| 유형 | 규칙 | base | 적용 | 비고 |
|------|------|------|------|------|
| 블로그 | V3 (TL;DR) | 권장 | 프로필 따름 | B2 |
| 블로그 | P8 (문단 전환) | 권장 | **필수** | 읽히는 글이어야 함 |
| 블로그 | V1 (밀도 균형) | 권장 | **필수** | 외부 독자 스캔 패턴 |
| 블로그 | T8 (구어체·감정체 동사) | 필수 | 필수 + 강화 | 공신력 손상이 블로그에서 더 큼 |
| 블로그 | ai-tells S1 전체 | 차단 | **0건 합격선** | B 등급 미만 시 재윤문 |
| 위키 | CJ3 (외래어 표기) | 부분 판별 | **필수** | 위키도 블로그 발행 원본 |
| 위키 | V3 (TL;DR) | 권장 | 프로필 따름 | 담긴 문서 종류를 따름. 시리즈 인덱스는 자체 요약 유지 (W3) |
| 위키 | H1 (단일 H1) | 가능 판별 | **본문 H1 금지** | W4 (위키 provider API 제약) |
| 위키 | ai-tells 전체 | 차단 | 차단 (조직 용어는 Do-NOT) | 조직 시스템명·약어는 마스킹 대상이지 AI 티 아님 |
| 정보성 | P3 (주제문 선행) | 부분 판별 | **필수** | I1 (섹션 독립성) |
| 정보성 | H4 (헤딩 형태 통일) | 부분 판별 | **필수** | 점프 독자가 헤딩으로 인덱스 인식 |
| 정보성 | C1 (코드 언어 명시) | 필수 | **강화** | 따라하기 시 구문 강조가 필수 |
| 정보성 | L1 (목록 항목 수) | 부분 판별 | **필수** | 절차 항목이 8개 이상이면 그룹화 |
| 정보성 | V3 (TL;DR) | 권장 | 권장 | 짧은 가이드는 없어도 무방 |
| 지식 | V3 (TL;DR) | 권장 | 완화 | 짧은 노하우는 없어도 무방 |
| 지식 | P5 (열거 vs 산문) | 필수 | 완화 | 비교표를 앞세운다 |
| 지식 | ai-tells D-4 (혁신적인) | 필수 | 필수 | 지식형도 과장 형용사는 금지 |
| 지식 | PAAR | (블로그 필수) | **경량** | K2 |
| PoC | V3 (TL;DR) | 권장 | **필수** | PC1 |
| PoC | P6 (코드 블록 설명) | 필수 | **강화** | PC3 (코드·결과·해석 순서) |
| PoC | C3 (긴 코드 분할) | 가능 판별 | **필수** | 코드 비중이 높아 분할 없이는 가독성 손상 |

## 3. 합격선

유형마다 통과 조건이 다르다. `없으면 합격 불가` 로 표시된 항목은 다른 항목이 모두 통과해도 불합격이다.

| 유형 | 합격선 |
|------|--------|
| 블로그 | A 등급: S1 0건, S2 ≤2건, PAAR 네 부분 모두 1문단 이상 / B 등급: S1 0건, S2 ≤4건 / C 이하: 게시 보류, 재윤문 |
| 위키 | 블로그보다 느슨하다 (작성 빈도 우선). B 등급 이상이면 발행 후보이고, 발행 시점에 `content-publish` 가 A 등급으로 가공한다 |
| 정보성 | 각 H2 섹션의 독립 가능성 필수 · 코드 블록 언어 명시 100% · 트러블슈팅형은 증상 인덱스 표 필수 |
| 지식 | K1 통과 (AI 가 쓸 수 없는 문장 3개 이상) · 경량 PAAR 의 Analyze 에 저자 판단 명시 |
| PoC | 결론 섹션의 판정 명시 · TL;DR 3요소(판정·수치·한계) · 검증 섹션의 가설-실험-판단 순서(PC7) · 후보가 있었는데 비교표와 선택 사유가 없으면(PC8) 불합격 / **없으면 합격 불가**: 환경 섹션의 버전·설정, 배경 섹션의 사전 성공 기준(PC5), 검증 섹션의 성공+실패 동시 기록(PC6) |
| 이슈 (버그) | 5요소(ISS1) 모두 포함 · 재현 절차 명령어·코드 형태 · 영향 범위 명시 |
| 이슈 (기능·운영) | ISS5 의 What/Why 구조 · ISS5 도메인 추상화 금지 항목 표의 정규식 미히트 · "변경 범위"·"구현 방안"·"검증 절차" 섹션 부재 |
| 장표 | 비교·대조를 담은 장마다 결론 1개(D1) · 마지막 장이 앞 장 결론의 반복이 아닌 결정(D2) · 표에 결론 없이 끝나는 장 0건 |
| 아키텍처 | 그림마다 층이 명시됨(AR1) · 손으로 그린 4층 그림 0건(AR2) · 렌더 결과를 확인함(AR5) · 쓴 패턴마다 기각 근거가 있음 / **없으면 합격 불가**: 1층·2층 그림, "하지 않은 선택" 절 |
| 데일리로그 | 라벨 부착률 100% · 항목당 1-2 문장 · 티켓·수치 동반 권장 |
| 동료리뷰 | 강점·개선점이 구체 사례 기반(PR1) · 강점:개선점 비율 1:1 또는 1:0.5(PR2) · 개선점이 행동 변화 가능 표현(PR3) · 평가서 어휘(PR4) 0건 |
| 성과평가 | 모든 성과가 데일리로그·PR·티켓·메트릭 근거(WR1) · PAAR 정량(WR2) 수치 동반 항목 비율 80% 이상 · 조직 기여와 개인 성장 분리(WR3) · 성과 어휘 회피(WR5) |
